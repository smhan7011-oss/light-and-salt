# 빛과 소금 · 상세페이지 & 스마트스토어 도구

## Windows 시작 방법

1. Python 공식 사이트 https://www.python.org/downloads/windows/ 에서 Python 3.12 이상을 설치합니다. 설치 시 Python Launcher도 포함하세요.
2. ZIP을 폴더에 **모두 압축 해제**합니다. ZIP 안에서 실행하지 마세요.
3. `start-windows.bat`을 더블클릭합니다. 첫 실행 때 가상환경과 bcrypt 의존성을 설치하므로 인터넷 연결이 필요합니다.
4. 브라우저가 열리면 ‘API 연결 및 상품 등록 화면 열기’를 누릅니다. 서버 창을 닫으면 프로그램이 종료됩니다.
5. 커머스API센터에서 발급한 애플리케이션 ID와 시크릿을 입력하고 ‘저장 및 연결 확인’을 누릅니다. API센터에 등록한 공인 IP와 이 컴퓨터가 사용하는 인터넷 회선의 공인 IP가 같아야 합니다.

**이 배포본은 Python 기반 Windows 실행 도구(.bat)이며 단독 실행형 .exe는 아닙니다.** 현재 Linux에서 검증했고 Windows 실제 실행과 실계정 API 연결은 아직 검증하지 않았습니다.

## 인증 정보

네이버 인증 서명을 서버에서 bcrypt로 생성하고 SELF 유형의 토큰을 요청합니다. 인증 정보는 브라우저 저장소나 소스 파일에 넣지 않습니다. 저장을 선택하면 Windows DPAPI로 암호화한 파일을 `%LOCALAPPDATA%\LightAndSaltStudio\credentials.bin`에 보관합니다. 동일한 Windows 사용자 계정에서 사용하세요. ‘인증 정보 삭제’는 파일과 현재 메모리의 인증을 삭제합니다. 네이버에서 이미 발급된 토큰의 원격 폐기를 의미하지는 않습니다.

시크릿을 채팅·저장소에 공유하지 마세요. 서버는 127.0.0.1에만 바인딩하고 Host/Origin/CSRF를 검사합니다. 웹에 직접 공개하는 서버가 아닙니다. Windows 외에는 영구 저장을 지원하지 않으며 ‘암호화하여 저장’을 해제하고 메모리에서만 시험할 수 있습니다.

## 상세페이지

상품명·가격·원본 사진·확인된 소구점 3가지를 입력하고 구성안을 검토한 뒤 이미지 제작을 누릅니다. 각 PNG는 860×1100이고 ZIP에 미리보기와 같은 PNG가 들어갑니다. 제품 사진은 비율을 유지하고 변형하지 않습니다. AI 사진 생성은 구현하지 않았습니다. AI 키를 설정하면 사진 기반 제품 분석·소구점 초안 작성을 사용할 수 있습니다. 상품 입력 내용은 브라우저 메모리에 보관되고 새로고침하면 지워집니다. AI 분석 시에는 상품명과 사진을 OpenAI로 전송합니다. 내려받은 결과를 보관하세요.

## 커머스 API 기능과 한계

- 인증 및 스토어 채널 조회: `/v1/oauth2/token`, `/v1/seller/channels`
- 주소·카테고리 조회: `/v1/seller/addressbooks`, `/v1/categories`
- 원본/상세페이지 이미지 업로드: `/v1/product-images/upload`
- 상품 등록: `/v2/products`

상품 등록은 현재 **고급 JSON 입력 방식**입니다. 일반 사용자를 위한 카테고리별 입력 폼·주소 선택 드롭다운·상세페이지 자동 업로드/연결은 아직 없습니다. 예시는 빈칸을 채우지 않고 등록할 수 없습니다. 실제 카테고리에 맞는 상품정보제공고시, 원산지, A/S, 배송사 코드, 출고지·반품지 ID, 배송비 정책 등을 네이버 규격에 맞게 작성해야 합니다. 모든 API 필수 항목을 로컬에서 검증하지 않으며 네이버가 최종 검증합니다.

첫 등록은 `smartstoreChannelProduct.channelProductDisplayStatusType`을 `SUSPENSION`(전시중지)으로만 허용합니다. 등록된 상품을 판매자센터에서 확인한 뒤 직접 전시 설정하세요. 기본 배송비는 4,000원으로 검사합니다. 반품비·교환비는 사용자의 실제 정책을 입력하세요. 인증만 연결했다고 스토어에 저장된 배송/반품 설정이 상품 등록 JSON에 자동 적용되지는 않습니다.

‘입력값 검토’는 네이버에 상품을 생성하지 않습니다. 검토한 내용을 보고 ‘상품 등록’ 확인 문구를 입력한 후 실제 등록 버튼을 눌러야 생성 요청을 보냅니다. 각 검토 티켓은 한 번만 사용하며 자동 재시도하지 않습니다. 등록 요청 중 오류나 시간 초과가 나면 판매자센터에서 생성 여부를 확인한 뒤 재시도하세요. 사진 업로드는 해당 버튼을 누를 때 즉시 수행됩니다.

## 개발 및 검증

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python server.py --port 8000
.venv/bin/python -m unittest discover -s tests -v
```

Windows에서는 `.venv\Scripts\python.exe`를 사용합니다. 서명/토큰 캐시, 오류 정보 제한, CSRF 차단, 검토 후 1회 등록 테스트를 포함합니다. 외부 등록 테스트는 mock 사용이며 실제 상품을 만들지 않습니다. Linux Chromium으로 이미지 제작, ZIP 무결성, 인증 화면 및 최종 확인 동작을 검증했습니다. Windows DPAPI, 네이버 실계정 권한·주소·이미지 업로드·상품 등록은 사용자의 컴퓨터에서 별도로 검증해야 합니다.

## 고정 출고지·반품지

API 연결 화면의 ‘이 컴퓨터에 고정할 출고지·반품지’에 주소를 한 번 입력하고 저장하세요. 주소는 GitHub 코드에 포함하지 않고 이 컴퓨터의 사용자 설정 폴더에 `shipping.json`으로 저장합니다. 앱을 다시 열어도 불러옵니다. 주소 ID를 확인했다면 함께 저장하고 ‘저장된 주소 ID를 상품에 적용’을 누르세요. ID가 없으면 주소 문자열 저장만 가능하며 상품 등록에 임의의 ID나 주소를 보내지 않습니다. 이 설정은 네이버 주소록 자체를 수정하지 않습니다.

## 실행 시 자동 업데이트

이 기능을 포함한 버전을 한 번 받은 뒤에는 같은 폴더의 `start-windows.bat`만 실행하세요. 먼저 GitHub의 업데이트 목록을 확인하고, 새 파일의 SHA-256을 모두 확인한 다음 적용합니다. 다운로드 실패·해시 불일치 시 새 코드를 적용하지 않고 기존 버전으로 실행합니다. 기존 코드에 직접 수정한 내용이 있으면 덮어쓰지 않습니다. 이전 파일은 `.update-backups`에 보관합니다. 버전 정보는 `update-manifest.json`에 있습니다.

인증 정보와 주소는 프로그램 폴더 밖의 사용자 설정 폴더에 있어 업데이트 대상에 포함되지 않습니다. 실행 중인 서버 창을 닫고 다시 실행해야 업데이트를 적용합니다. 현재는 실행 중 실시간 업데이트나 Windows 서비스 자동 재시작을 지원하지 않습니다. 서버 포트(8000)를 다른 프로그램이 쓰면 자동 업데이트하지 않습니다. 자동 업데이트로도 아직 미구현된 기능이 즉시 생기는 것은 아닙니다.

배포 시 유지관리자는 `updater.ALLOWED`에 선언된 배포 파일의 SHA-256으로 `update-manifest.json`을 갱신하고 함께 커밋해야 합니다. HTTPS 인증을 유지하며 이 저장소의 main 코드만 가져옵니다.


## 사진 기반 AI 자동 작성

OpenAI API(모델 `gpt-4.1-mini`)의 별도 키와 사용 가능한 API 결제 계정이 필요합니다. ChatGPT 구독과 API 결제는 별도입니다. https://platform.openai.com/api-keys 에서 키를 만들고, 메인 화면 ‘AI 자동 작성 설정’에 입력하세요. 키는 채팅·저장소에 공유하지 마세요. Windows 암호화 저장을 선택하면 사용자 설정 폴더의 `ai-credentials.bin`에 DPAPI로 저장합니다. 네이버 ID·시크릿은 OpenAI 요청에 포함하지 않습니다. 설정 저장은 키의 유효성을 검증하지 않으며 첫 분석에서 API 접근이 확인됩니다.

1. 상품명을 입력하고 사진을 선택합니다. AI 키가 있고 ‘사진 선택 시 AI 자동 분석’이 선택되어 있으면 자동 분석합니다. 수동 버튼으로 다시 분석할 수도 있습니다.
2. 사진의 시각적 특징·라벨에서 소구점 최대 3개와 브랜드, 구성, 소재/원재료, 제조사, 사용방법, 보관/주의사항, 식품 주원료·함량 및 부원료를 추출합니다. 읽을 수 없는 항목은 빈칸과 확인 필요로 남깁니다. 이미지에 제조사·원료 정보가 없으면 라벨 사진을 추가하세요.
3. 근거 사진 번호와 읽은 문구를 확인하고 ‘AI 초안을 확인했습니다’를 체크합니다. 이후 구성안과 상세페이지를 제작합니다. 실제 사실 여부를 프로그램이 독립적으로 검증할 수는 없습니다.

AI 분석을 실행하면 상품명과 선택한 사진(최대 11장)을 로컬 서버를 통해 `api.openai.com`으로 전송하며 API 사용료가 발생할 수 있습니다. 사진은 분석용 사본만 최대 2048px JPEG로 변환하고 원본 제품 이미지와 최종 이미지에는 영향을 주지 않습니다. 앱 서버에 사진을 파일로 저장하지 않습니다. 라벨 글씨가 작거나 흐리면 추출하지 못할 수 있습니다. 민감한 개인정보가 있는 사진은 선택하지 마세요.

라벨에 없는 제조사·원재료·함량·사용량·보관법을 추측하지 않도록 지시하고, 근거 없는 항목과 과도하게 긴 값은 자동 입력에서 제외합니다. 정확한 주의사항을 길이 제한 내에 옮길 수 없으면 임의 요약하지 않고 확인 필요로 표시합니다. 세 개의 차별점을 입증할 수 없으면 가능한 개수만 제안합니다. 기존 수동 입력은 기본적으로 유지합니다. ‘기존 입력값도 바꾸기’를 선택하면 덮어씁니다. 상품명/사진 변경 시 이전 자동 입력은 제거하며 직접 수정한 값은 유지합니다.

AI 응답 형식·근거 요구·초안 검토·기존 입력 유지·오래된 분석 결과 차단·이미지 생성의 모의 테스트를 수행했습니다. 실제 키를 이용한 분석과 Windows AI 키 암호화 저장은 별도 실계정 검증이 필요합니다. 긴 구매 정보는 여러 ProductInfo 이미지로 나누어 표시합니다.

## 채팅에서 분석 → 프로그램에 가져오기 (기본 방식)

OpenAI API 키와 API 호출 없이 사용할 수 있습니다. 이 채팅에 상품명·가격·상품 사진·라벨 사진을 올리고 아래 형식의 ‘프로그램 가져오기용 JSON’을 요청하세요. 메인 화면의 ‘채팅 결과 가져오기’에 JSON 전체(코드 블록 포함 가능)를 붙여넣고 ‘내용 가져오기’를 누릅니다. 원본 사진은 분석할 때의 순서대로 프로그램에서 직접 선택합니다. 확인 체크 후 구성안과 PNG/ZIP을 만듭니다. 채팅 결과는 로컬 브라우저에서 파싱되며 가져오기/제작 과정에서 유료 AI 분석을 호출하지 않습니다. 유료 자동 분석은 기본적으로 꺼져 있고, 가져오기를 성공해도 꺼진 상태를 유지합니다. 채팅 서비스 자체의 이용 조건은 별개입니다.

```json
{
  "format": "light-salt-product-v1",
  "product": {
    "name": "사용자가 제공한 정확한 상품명",
    "price": 10000,
    "brand": "",
    "options": "",
    "size": "",
    "material": "",
    "maker": "",
    "target": "",
    "usage": "",
    "caution": "",
    "ingredient": "",
    "additional": ""
  },
  "points": ["사진에 근거한 소구점 1", "사진에 근거한 소구점 2", "사진에 근거한 소구점 3"],
  "pages": [
    {"section": "hero", "headline": "메인카피", "description": "짧은 소개", "image": 1},
    {"section": "point1", "headline": "첫 번째 소구점 카피", "description": "확인된 특징의 고객 가치", "image": 1}
  ],
  "notes": ["확인되지 않는 제조사·원료·함량 등은 비워두고 확인할 사항을 작성"]
}
```

위 내용은 형식 예시이며 실제 상품 정보가 아닙니다. 가격은 확인된 실제 정수만 사용합니다. 알 수 없으면 `price`를 생략하거나 null로 두고 사용자가 직접 입력하도록 합니다. `product` 문자열은 알려진 정보만 작성하고 미확인 항목은 빈 문자열로 둡니다. 원재료·제조사·함량·주의사항을 추측하거나 긴 주의사항을 임의로 잘라 적지 않습니다. 3가지 소구점을 뒷받침할 정보가 부족하면 제품 디테일 사진이나 추가 설명을 요청하고 완성된 결과처럼 꾸미지 않습니다.

문자수 제한: brand 35, name 55, options/size/maker 100, material 160, target/usage/caution/ingredient/additional 180. 소구점은 각 90자 이하 3개입니다. 제한을 넘으면 전체 가져오기를 중단하고 원래 입력을 유지합니다. 미확인 정보나 길이 제한 때문에 담지 못한 정보는 notes(각 500자 이하, 최대 20개)에 별도로 설명합니다. notes는 제작 전 검토용으로만 보이고 상세 이미지에 인쇄되지 않습니다.

`pages`는 선택 항목이며 최대 9개입니다. section은 hero / introduction / point1 / point2 / point3 / ingredient / additional / target / usage 중 하나입니다. 제목 headline은 90자 이하, 설명 description은 180자 이하 문자열이고 사진 번호 image는 1~11 정수입니다. hero는 상품명 대신 보조 메인카피만 바꿉니다. 핵심가치는 points로 만들고 구매 정보 표는 product의 실제 정보로 생성하여 pages에서 임의로 대체하지 않습니다. 원료·추천대상·사용방법 페이지를 지정했다면 해당 제품 정보가 실제로 입력되어 있어야 합니다. 없는 사진 번호를 지정하면 제작을 중단하고 사진 추가를 안내합니다.

이미 입력된 값과 다른 내용은 교체 체크를 하기 전까지 덮어쓰지 않습니다. ‘기존 상품 정보를 가져온 내용으로 교체’를 체크하면 이전 상품 필드를 비운 뒤 새 내용을 적용하므로 이전 제품 정보가 섞이지 않습니다. ‘가져온 페이지 구성 해제’는 사용자 입력은 유지하고 페이지별 카피/사진 지정만 해제합니다. 원본 사진과 가져온 내용을 사용자가 확인해야 구성안을 만들 수 있습니다. 상품 입력 변경 시 확인 체크가 초기화됩니다.
